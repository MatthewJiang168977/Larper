# M9 — Profile & Taste Identity
Goal: a private profile expressing each user's niche taste — taste palette, taste archetype, niche stats — plus an optional shareable card. Everything derived from existing data (taste vector, check-ins, place rarity), not self-reported labels.
Non-goals: no social graph; no public check-in history or map of visited places; no MBTI/self-reported personality.
Privacy (hard rules): profiles private by default; sharing is explicit opt-in per card. Share cards show aggregates only (palette, archetype, counts, niche-score percentile, rarest category) — never places, addresses, coordinates, timestamps, or "recently visited". Share links: unguessable random token, revocable, no user ID. Document in README trade-offs.
1. profile-stats consumer (Go): new consumer group on user.events (second consumer — the Redpanda fan-out justification). Idempotent (processed_events per consumer group). Projection: check-in count, distinct neighborhoods (geohash5), current/longest streak, niche score (mean rarity of checked-in places) + percentile, rarest category, accept/skip ratio. Rebuildable via a command; check Redpanda retention — if not infinite, rebuild from Postgres and document why. Consumer lag as a Prometheus metric + Grafana panel.
2. Taste palette: deterministic taste vector → 3–5 colors + wave params; stable hue per tag family, weighted by top families. Same vector → same palette (unit test). Rendered client-side.
3. Taste archetypes: offline k-means (k≈8–12) over taste vectors, clusters named from top tags via a curated name map. Online nearest-centroid assignment. Cold start: none until ≥5 check-ins/accepts ("still surveying your taste"). Seed clustering with synthetic vectors from the taxonomy (few real users); document it.
4. Profile + share card: GET /me/profile; POST /me/share-card → token; DELETE to revoke; public GET /share/:token → aggregate-only card + server-rendered OG image; rate-limited.
5. Optional, last: playful opt-in star sign from archetype (never require birthday; store month/day only).
Acceptance: consumer idempotent (duplicate-event test) and rebuildable (identical stats); lag in Grafana; chaos test kills consumer with no lost/double-counted stats; palette deterministic; share-card payload test asserts no place names/coords/timestamps; README M9 section + ADR in docs/decisions/ ("separate consumer vs computing in API", "aggregate-only sharing").
