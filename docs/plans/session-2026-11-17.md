## 3. Export and delete (#99, #101)

- **API (#99):**
  - `GET /me/export` returns one consistent read-only snapshot.
  - `DELETE /me/history` keeps the account and taste profile; `DELETE /me` removes
    everything.
  - Both deletes go through SECURITY DEFINER functions in migration 0020; the API role still
    has no DELETE grant.
  - **The demo account is refused on all three**, with 403 `demo_account`. Exporting it would
    leak other visitors' data, including `offeredFrom` positions. The automated security
    review and the independent reviewer both caught this.
  - taste-worker no longer stalls on events for a deleted user.
  - Clerk deletion sits behind `CLERK_DELETE_USERS`, off by default and tested with mocks
    only.
- **Backups** (`docs/decisions/0005-data-deletion.md`): deleted rows can stay in backups for
  **about 3 weeks, 60 days at most**. The settings behind that are `retention: 14d` with
  weekly base backups, plus the bucket's 60-day lifecycle rule. A restore would bring deleted
  rows back. Redpanda topic retention isn't set anywhere, so the broker default applies: 7
  days per the docs, not checked on the cluster.
- **Web (#101):**
  - A "your data" panel in the journal, with in-page confirmations that need "delete" typed.
    The demo account sees no actions.
  - The /privacy page has a new "Your data" section.

## 4. Hours pilot (#98) and the markup check

- **Tooling:**
  - `scripts/hours-pilot-candidates` is a read-only export of the top 50 gated candidates per
    focus area, written to `pilot/` (gitignored).
  - `workers/cmd/hours-pilot-import` is dry-run by default and needs `-apply` to write. It
    validates with the Go parser and upserts `source='manual'`.
  - `data/focus-neighborhoods.geojson` holds the three approximate polygons.
  - Not run against any database.
- **Markup check (decision doc step 3): 19.5%.**
  - 40 of the 205 home pages that loaded have schema.org `openingHours` markup. That's 13.3%
    of the 300 sites sampled.
  - 90 sites failed to load and 5 disallowed it in robots.txt.
  - The margin is about ±5 points, so even the high end is under a third. **Per the decision
    doc, don't build the website pipeline; keep verifying by hand.** I stopped there.
  - **Method:**
    - The place list came from local `data/nyc.parquet` (Overture), not production: places
      inside the polygons, confidence 0.7 or higher, not a blocked category, not a chain, a
      quest-type top category (food and drink, shopping, arts and entertainment, culture,
      sports and recreation), and a website that isn't a social or aggregator site. That
      gave 3,252 unique sites, of which 300 were sampled at random with seed 20261117.
    - Each site got one page request plus its robots.txt, with an identifying User-Agent, a
      10 s timeout, a 2 MB cap and 1 s pacing.
    - Only the counts were kept.
